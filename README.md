# mongol-bichig

The single source of truth for traditional Mongolian script (Mongol bichig,
ᠮᠣᠩᠭᠣᠯ ᠪᠢᠴᠢᠭ) across the gege tools — one repository wearing three faces:

| Face | What | Who it's for |
|---|---|---|
| **Knowledge base** | [`skills/mongol-bichig/references/`](skills/mongol-bichig/references/) — nine source-cited documents on the encoding model, history, variation sequences, script styles, suffixes, legacy encodings, fonts and orthography | humans |
| **Agent skills** | [`skills/`](skills/) — installable with `npx skills add gege-mn/mongol-bichig` | coding agents |
| **npm package** | `@gege-mn/mongol-bichig` — the suffix registry, Classical romanization and Unicode character classes | code |

Nothing here is specific to one tool. [gege-linter][linter] validates bichig
text and [gege-convertor][convertor] generates it; both read their shared facts
from here rather than keeping private copies, which is exactly why this
repository exists — the suffix registry had already been forked once.

[linter]: https://github.com/gege-mn/gege-linter
[convertor]: https://github.com/gege-mn/gege-convertor

## Install

```sh
npx skills add gege-mn/mongol-bichig   # the skills — pick which at install time
pnpm add @gege-mn/mongol-bichig        # the data and primitives
```

## The package

```ts
import { connectorSuffixes, toScript, harmonyOf, MVS } from '@gege-mn/mongol-bichig';

toScript('qar-a');        // → ᠬᠠᠷ⟨MVS⟩ᠠ  ('-' is the connector)
harmonyOf(toScript('ün')); // → 'feminine'

connectorSuffixes.find((s) => s.translit === 'iyar');
// { sequence: 'ᠢᠶᠠᠷ', translit: 'iyar', cyrillic: '-аар/-оор',
//   category: 'instrumental', harmony: 'masculine', after: 'consonant',
//   join: 'mvs', registry: true }
```

Exports: `suffixes` (all 67 entries), `connectorSuffixes` (the 63 joined by
MVS), `spaceParticles` (the 4 that take a plain space and must never be
connector-joined), `suffixByTranslit`, `suffixesMatching`; `toScript`,
`fromScript`, `finalLetter`, `isRomanizable`; and the character classes
`MVS`, `NNBSP`, `NIRUGU`, `ZWJ`, `ZWNJ`, `FVS`, `isMongolLetter`,
`isHudumLetter`, `isVowel`, `isDigit`, `harmonyOf`, `cp`, `prevBaseCp`,
`uplus`.

Non-JavaScript consumers can read [`data/suffixes.json`](data/suffixes.json),
generated by `pnpm build`.

## How the data stays honest

Three properties, each enforced by a test rather than by discipline:

1. **Rows are authored in romanization, never in bichig.** Only `translit` is
   written by hand; the bichig `sequence` and the `harmony` class are derived
   from it through `toScript`. So no invisible character is ever typed as a
   literal, and a row cannot disagree with itself.
2. **The document is normative.** `test/suffixes.test.ts` parses the tables in
   `references/suffixes.md` and asserts that every one of its 52 code-point
   rows matches the data — sequence, transliteration, gender, attachment
   condition and shaping-registry flag. Editing one without the other fails
   the build, in either direction.
3. **Nothing is invented.** Every entry must appear somewhere in the reference
   document, including the 15 that are described in prose rather than
   tabulated.

## The rule that outranks the others

**Never type an invisible character as a literal** — MVS (U+180E), NNBSP
(U+202F), FVS1–4 (U+180B–180D, U+180F), ZWJ/ZWNJ, nirugu. Always `\uXXXX` in
code, always `U+XXXX` in prose. They are silently mistranscribed by editors,
clipboards and language models, and the resulting bug is by definition
invisible. `test/no-invisible-literals.test.ts` enforces this across `src/`,
`test/`, `skills/` and `scripts/`.

Visible bichig letters (ᠠ ᠨ ᠮ …) are fine as literals.

## Development

```sh
pnpm install
pnpm test        # vitest, including the document cross-check
pnpm typecheck
pnpm lint
pnpm build       # tsc → dist/, then regenerate data/suffixes.json
```

## Provenance

[`sources.md`](sources.md) pins every primary source the knowledge base rests
on, with the version and date each claim was verified against. It is the
re-verification checklist: when Unicode, UTN #57 or a font ships a new
version, that file says what to re-read.
