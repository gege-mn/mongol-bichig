# FVS variation sequences — the registry for `fvs-unregistered`

Researched 2026-07-25 against Unicode 17.0; re-checked 2026-11-05 against
Unicode 18.0. Sources: StandardizedVariants.txt (18.0.0, header date
2026-07-29, vendored in `vendor/unicode/`; 17.0.0 and the historical versions
4.1–17.0 diffed), mongfontbuilder `variants.json` (v0.15.3, vendored), UTN #57
v4, core spec §13.5 (16.0–18.0), L2/20-057, L2/26-163, L2/26-203. Invisibles
as `U+XXXX`: FVS1 U+180B, FVS2 U+180C, FVS3 U+180D, FVS4 U+180F, MVS U+180E.

## Which registry to trust — the headline finding

**Unicode 18.0 (2026-09-16) brought the UCD into line with the Chinese
standards** (UTC decision 188-C33, data in L2/26-203). Since then the UCD and
mongfontbuilder agree, but only mongfontbuilder says which writing system a
form belongs to.

- UCD 18.0 StandardizedVariants.txt: 117 Mongolian (base, selector) lines.
  111 are in use and give **251** (base, selector, position) triples. Six
  are labelled `not in use`: Todo OE + FVS1, Ali Gali A + FVS1/2/3, Ali Gali
  I + FVS1 and Ali Gali NGA + FVS1. Stability policy forbids deleting them
  (L2/26-091 asked to, and the UTC refused). FVS4 appears on **5 lines (9
  triples)**; 17.0 had none.
- mongfontbuilder (= living UTN #57): 253 triples across all locales; the
  Hudum (MNG) locale has **107**.
- **Every UCD triple is in mongfontbuilder, and all 107 Hudum triples are in
  the UCD** (17.0 had 39 of them). mongfontbuilder's two extras are Ali Gali:
  KA final + FVS1 (Hudum Ali Gali) and SIBE GA medial + FVS3 (Manchu Ali
  Gali). The UCD's two position-less Ali Gali rows (U+1880, U+1881 + FVS1)
  are in no mongfontbuilder locale. `test/fvs.test.ts` fails if this changes.
- **The UCD has no writing-system field.** 144 of its 251 triples belong to
  Todo, Sibe, Manchu or Ali Gali only. Validated against the UCD alone, Hudum
  text would accept NA medial + FVS3, which only Manchu Ali Gali uses.
- 12 of 17.0's 93 triples are gone from 18.0 and from every mongfontbuilder
  locale. Eight belong to the six `not in use` pairs. The other four were
  dropped from the position lists of pairs that stay in use: U+1820 medial
  FVS2, U+1835 medial FVS1, and U+185E SIBE I final FVS1 and FVS2.
- The 18.0 core spec still prints the old warning that the list "has not yet
  been updated to synchronize with … UTN #57". The data has been fixed and
  the prose has not: the UTC gave Liang Hai that edit as action item 188-A69.

**Rule: validate Hudum against mongfontbuilder's MNG locale.** The package
ships it: `hudumFvs` and `fvsStatus` in `src/fvs.ts`, generated by
`scripts/gen-fvs.mjs` into `src/data/fvs.ts`. Use the UCD to *explain* a
rejection: a form valid only in another writing system, or one Unicode
labels `not in use`, gets its own message.

## What an FVS means

Current model: **FVSn is a fixed index into that letter's per-position
variant registry**, aligned with GB/T 25914—2023's "first/second/third/fourth
form" glyph numbering. Three non-obvious properties:

1. **Same FVS, same letter, different meaning per position.** QA + FVS2 =
   feminine G form in init/medi but "third isolated form" in isol; A + FVS2 =
   chachlag Aa in isol but the default in fina.
2. **Defaults are deliberately FVS-selectable** (31 of the 107 MNG triples
   select the form default shaping would produce). This is *load-bearing*,
   not redundant — it pins a form against context. Canonical case:
   `MVS + a/e + FVS` cancels chachlag (UTN #57: "a e if follows an MVS and
   precedes an FVS: Default"). A naive "redundant FVS" rule would flag
   correct text.
3. **An FVS can change a *neighboring* character's form**: ö/ü final takes
   the marked form "if … follows an FVS2 or FVS4 that follows h or g in
   initial position" — an EAC-mandated wart UTN #57 acknowledges. FVS is not
   a pure postfix modifier.

Pre-2017, FVS meanings were the vague 2005 chart descriptions and vendors
implemented mutually incompatible assignments (Menksoft vs Baiti vs Founder).
Sharpest legacy trap: U+182C/U+182D + FVS3 medial was the double-dotted
"fourth form" in pre-2017 fonts but selects the *first/masculine* H form in
the current model. The double-dotted form moved to **FVS4**. Same bytes,
different glyph across model generations; not warnable from bytes alone, but
document it. UCD 18.0 still calls FVS3 the "fourth form" and FVS4 the "fifth
form": its header says these labels are arbitrary and do not describe the
glyphs. mongfontbuilder's docs say bluntly: do **not** implement from UTR
#54's variant tables.

**FVS4 (U+180F)**, encoded Unicode 14.0 via L2/20-057, exists solely for
pre-contemporary orthography (dotted isolated I/U, double-dotted kaph G on
QA/GA). Only QA and GA take FVS4 in Hudum. The UCD had no FVS4 sequences
before 18.0, which added nine.

**17 Hudum letters take no FVS at all** — any FVS after them is unregistered:

Position-aware refinement (second tier, optional): e.g. U+1820 + FVS3 is
registered in isol only; U+1820 + FVS4 is registered nowhere (and Noto
v3.002 renders it as a visible `fvs4` marker — verified by hb-shape). The
full 107-triple table with written units, default flags, `archaic`/
`unrecommended` status and GB form names lives in the vendored data; the
schema is below.

## variants.json schema notes (vendoring traps)

```
variants[characterName][position]["0"|"1"|"2"|"3"|"4"] = {
  written: WrittenUnitID[] | [position, fvs, locale?],  // or cross-reference
  default?: true,
  locales: { MNG?/MNGx?/TOD?/TODx?/SIB?/MCH?/MCHx?: {
    conditions?: string[], archaic?: true, unrecommended?: true,
    gb?: string, eac?: string } }
}
```

- **Key `"0"` means "context-only form, no FVS assigned" — not FVS0.**
  Off-by-one trap.
- `written: ["init", 4]` is a cross-reference ("fabricated variant").
- A `default: true` entry *with* an FVS number means the default is
  explicitly selectable (see load-bearing defaults above).
- Locale is a **text-level property, not a code-point property**: the same
  letter has different registrations per locale (U+1828 medial FVS3 is valid
  only as Manchu Ali Gali). A Hudum linter validates against MNG only.
  Hudum Ali Gali (MNGx, Buddhist transcription) is out of scope for our
  tools: the repository owner ruled on 2026-11-05 that `fvsStatus` reports
  its forms as `other-writing-system`. Locale triple counts: MNG 107, MNGx 22, TOD 46,
  TODx 36, SIB 59, MCH 71, MCHx 97. **From v0.13.0 (2026-10-02):** MNGx 23
  and MCHx 98, 253 deduplicated. `variants.json` is byte-identical in
  v0.15.3, the vendored copy. MNG is still 107 and the Hudum quick-reference
  table above is unchanged; `test/fvs.test.ts` checks the table against the
  data.
- The three `unrecommended` Hudum variants (JA fina FVS1, YA medi FVS2,
  WA medi FVS1) exist only in this data. UCD DoNotEmit.txt has no Mongolian
  entries, 18.0 included.
- If parsing raw StandardizedVariants.txt: the U+1880/U+1881 lines have an
  **empty positions field** — a positions-required parser silently drops them.

## SHA before I — the default drops the dots

UTN #57 gives SHA (U+1831) a **dotless** form, written unit `S`, in initial
and medial position, and mongfontbuilder's MNG locale makes it the *default*
under the `dotless` condition: SHA directly before I (U+1822). FVS1 selects it
explicitly; **FVS2 selects the dotted form `Sh`** (a load-bearing default,
point 2 above). So a bare U+1831 U+1822 draws exactly like U+1830 U+1822,
and a reader sees SA.

That breaks ordinary Mongolian words. The dictionary spells жишээ
U+1835 U+1822 U+1831 U+1822 U+1836 [MVS] U+1821 (`ǰišiy-e`) and жишиг
U+1835 U+1822 U+1831 U+1822 U+182D (`ǰišig`), with no selector, and both
render as if spelled with SA. Native words whose ш is spelled with SA
(шинэ `sine`, шил `sil`) are not involved: the condition is on the letter
SHA.

Measured with hb-shape on Noto Sans Mongolian 3.103 (2026-11-07):

| SHA followed by | Initial | Medial |
|---|---|---|
| I (U+1822) | `S` (dotless) | `S` (dotless), also when the I is final |
| FVS2 + I | `Sh` | `Sh` |
| FVS1 + I | `S` | `S` |
| ZWJ + I | — | `Sh` |
| any other letter (A E O U OE UE EE NA BA MA LA TA YA RA tested) | `Sh` | `Sh` |
| MVS or NNBSP, then I | — | SHA takes its final form, `Sh` |

**Ruled 2026-11-07 by the owner: SHA before I is written with FVS2.** In
Mongolia ᠱ is written precisely so that the reader sees ш, so the dotless
default is never the intended reading. The rule goes by letters, with no
word list: in Mongolia ᠰ and ᠱ are different letters, so every ᠱ before ᠢ
gets the dots, guessed words included (confirmed by the owner the same
day). The package carries the ruling in both directions:

- `toScript` writes `ši` as SHA + FVS2 + I (`š1i` asks for the dotless form,
  `š.i` writes the bare pair), so the converter's output is dotted.
- `undottedSha(text)` returns the offset of every bare SHA I in existing
  text, for gege-linter's fix: insert FVS2 after the SHA.

## Linter rules derived

1. **Placement (`fvs-placement`, shipped)** — normative backing, core spec:
   a selector "immediately follows the base character it modifies"; any FVS
   "not immediately preceded by one of their defined base characters will be
   ignored". FVS after space/NNBSP/MVS/digit/punctuation/another FVS/ZWJ/
   string start = dead invisible character → error. Subsumes doubling.
2. **Registration (`fvs-unregistered`, shipped in gege-linter 0.12.0 on 0.3.1's data)** —
   `fvsStatus(base, fvs, position?)` returns one of four answers:
   - `registered`: fine.
   - `other-writing-system`: warning. The form is valid in Todo, Sibe, Manchu
     or Ali Gali text, not Hudum.
   - `not-in-use`: Unicode 18.0 withdrew the sequence. Info: none of the six
     is Hudum.
   - `unregistered`: warning. No mongfontbuilder locale registers it. That
     includes U+1880 and U+1881 + FVS1, two Ali Gali rows the UCD lists
     without positions.

   Without a position the check is per letter (the table above). Passing the
   cursive position from the linter gives the exact answer.
3. **Legacy ZWJ ordering** — `letter ZWJ FVS` (pre-standard ordering) is a
   dead selector today; flaggable with a mechanical swap fix to
   `letter FVS ZWJ`.
4. **Redundancy: mostly not lintable.** Only safe at info level when the
   selected form provably equals default shaping *and* no context rule
   consults FVS presence (chachlag cancellation, o/u/ö/ü marked-reset,
   neighbor effects). When in doubt, silent.
5. **Undotted SHA (`undotted-sha`)** — SHA directly before I, no selector:
   the font draws SA. Warning with a fix that inserts FVS2, safe to apply
   unasked because FVS2 selects the form the letter SHA exists for. FVS1 in
   that spot is deliberate and is left alone. Data: `undottedSha`; see
   "SHA before I" above.
6. Rendering note: unlike bare MVS (visible in Noto v3), a stray FVS in a
   *legacy* font is typically invisible — silent corruption for search and
   collation. Noto v3.002 renders unregistered/doubled FVS as visible
   `fvsN` marker glyphs (deliberate misuse-visibility; see
   `fonts-and-rendering.md`).
